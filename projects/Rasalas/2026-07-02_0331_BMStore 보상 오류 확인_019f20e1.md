### Assistant

짧게 정리하면:

- **다른 기획데이터를 참조해서 검증만 할 때:** `Check()`
- **다른 기획데이터를 참조해서 런타임용 캐시/연결값/파생값을 추가할 때:** `Connect()`
- **자기 엑셀/JSON 데이터만 읽어서 딕셔너리 구성할 때:** `ReadStream()` 내부의 `SetData()`
- **LiveIgnore 같은 필터링/제거 후처리:** `IgnoreDataRemove()`

근거는 [BaseLoader.cs](E:/Rasalas/Trunk/qa/Client/Assets/Script/SharedLib/DataManager/BaseLoader.cs:185)에 `Connect()`가 “다른 로더와 데이터 연결”, `Check()`가 “데이터 유효성 검사”로 분리되어 있고, [DataManager.cs](E:/Rasalas/Trunk/qa/Client/Assets/Script/SharedLib/DataManager/DataManager.cs:276) 로드 순서도 `ReadStream` 완료 후 `Connect()` → `IgnoreDataRemove()` → `Check()` 순서입니다.

```csharp
public override void Connect()
{
    base.Connect();

    // 다른 Loader 참조해서 런타임용 캐시/역참조/파생값 구성
    var otherLoader = DataManager.Get<LoaderOtherData>();
    _cache.Clear();

    foreach (var data in _datas.Values)
    {
        var other = otherLoader.GetData(data.OtherId);
        if (other == null)
            continue;

        _cache[data.Id] = MakeRuntimeValue(data, other);
    }
}

public override void Check()
{
    base.Check();

    // 유효성 검증만 수행
    var otherLoader = DataManager.Get<LoaderOtherData>();

    foreach (var data in _datas.Values)
    {
        if (otherLoader.GetData(data.OtherId) == null)
            PrintLogError($"OtherData 없음. Id:{data.Id}, OtherId:{data.OtherId}");
    }
}
```

주의할 점은 `ReadStream()`이나 `SetData()`에서는 가능하면 다른 Loader를 참조하지 않는 게 좋습니다. 이 단계는 각 파일을 읽고 자기 자료구조를 만드는 단계라, 다른 Loader가 아직 준비되지 않았거나 바이너리 생성/부분 로드 흐름에서 순서 문제가 생길 수 있습니다.

즉, “검사”는 `Check()`, “다른 테이블을 엮어서 메모리 구조를 완성”하는 건 `Connect()`가 맞습니다.

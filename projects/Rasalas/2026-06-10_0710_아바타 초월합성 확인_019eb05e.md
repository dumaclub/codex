### Assistant

네, **차감 안 된 것처럼 보일 수 있습니다.** 다만 원인은 치트키 때문이라기보다 **보상 아바타 ID와 대상 아바타 ID가 같은 경우**입니다.

현재 `AvatarMythTS()`에는 일반 아바타 합성처럼 `allsuccess` 치트를 직접 처리하는 코드가 없습니다. 즉 `/allsuccess`가 이 함수 안에서 별도로 성공률을 100%로 바꾸지는 않습니다.

성공 분기 안의 흐름은 현재 이렇게 되어 있습니다.

```csharp
AddAvatarCard(newAvatarId, count);   // 보상 먼저 지급
...
avatarEntity.UpdateStack(avatarEntity.stack -1); // 대상 1개 차감
```

문제는 현재 보상 `newAvatarId`가 `110`이고, 초월합성 대상 `tsAvatarId`도 `110`이면:

```text
보상 +1
대상 차감 -1
결과적으로 stack 변화 0
```

그래서 DB나 클라에서 보면 “성공했는데 대상 아바타가 차감 안 됐다”처럼 보일 수 있습니다.

예시:

```text
초기 stack: 3
성공 보상 AddAvatarCard(110, 1): stack 4
성공 차감: stack 3
최종 stack: 3
```

자기 자신을 재료로도 넣었다면:

```text
초기 stack: 3
재료 차감 -1: stack 2
보상 +1: stack 3
성공 차감 -1: stack 2
최종 stack: 2
```

즉 성공 차감 코드는 실행되지만, 보상 지급이 먼저 들어가서 상쇄될 수 있습니다.
이걸 명확히 하려면 성공 시 대상 1개 차감을 **보상 지급보다 먼저** 처리하는 쪽이 맞습니다.

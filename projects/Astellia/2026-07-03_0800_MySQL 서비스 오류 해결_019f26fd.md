### Assistant

`Unit mysql.service not found` 는 “MySQL 데이터가 사라졌다”는 뜻이라기보다, **systemd에 `mysql`이라는 서비스명이 등록되어 있지 않다**는 뜻입니다. TencentOS/CentOS 계열에서는 보통 서비스명이 `mysql`이 아니라 `mysqld` 또는 `mariadb` 입니다.

먼저 아래 순서로 확인해 보세요.

```bash
systemctl list-unit-files | grep -Ei 'mysql|mysqld|maria'
```

결과에 `mysqld.service`가 있으면:

```bash
systemctl start mysqld
systemctl status mysqld
```

`mariadb.service`가 있으면:

```bash
systemctl start mariadb
systemctl status mariadb
```

설치 상태도 확인해 보세요.

```bash
rpm -qa | grep -Ei 'mysql|mariadb'
which mysql
which mysqld
```

데이터 디렉터리가 남아있는지도 중요합니다.

```bash
ls -ld /var/lib/mysql
ls -al /var/lib/mysql | head
```

만약 `mysqld.service`도 없고 `mariadb.service`도 없다면, 가능성은 보통 셋 중 하나입니다.

1. MySQL 패키지가 삭제됨
2. MySQL이 tar.gz 방식으로 수동 설치되어 systemd 서비스가 없음
3. Docker나 다른 프로세스 관리 방식으로 실행 중이었음

추가로 확인:

```bash
ps -ef | grep -Ei 'mysqld|mysql'
docker ps -a | grep -i mysql
yum history | head
```

중요한 건 **바로 재설치하지 않는 것**입니다. `/var/lib/mysql`에 실제 데이터가 남아있을 수 있어서, 잘못 재설치하면 기존 데이터 경로를 덮거나 권한이 꼬일 수 있습니다.

우선 가장 가능성 높은 명령은 이것입니다:

```bash
systemctl start mysqld
systemctl status mysqld
```

그 결과를 보여주시면, 다음 단계로 로그 확인이나 복구 방향을 같이 잡아드릴 수 있습니다.

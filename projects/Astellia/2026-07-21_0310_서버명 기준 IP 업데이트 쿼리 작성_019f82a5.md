### Assistant

스크린샷처럼 SVN 서버를 데몬으로 띄우려면 Linux에서 아래 명령을 실행하면 됩니다.

```bash
svnserve -d -r /root/SVN
```

- `-d`: 백그라운드 데몬 실행
- `-r /root/SVN`: SVN 저장소들의 최상위 경로 지정
  예를 들어 `/root/SVN/GameProject` 저장소는 다음 주소로 접근합니다.

```text
svn://서버IP/GameProject
```

저장소가 아직 없다면 생성합니다.

```bash
mkdir -p /root/SVN
svnadmin create /root/SVN/GameProject
```

계정 인증을 쓰려면 `/root/SVN/GameProject/conf/svnserve.conf`를 다음처럼 설정합니다.

```ini
[general]
anon-access = none
auth-access = write
password-db = passwd
```

그 후 같은 폴더의 `passwd`에 계정을 등록합니다.

```ini
[users]
devuser = 비밀번호
```

실행 여부 확인:

```bash
ps -ef | grep svn
```

중지하려면 PID를 찾아 종료합니다.

```bash
pkill svnserve
```

외부 접속이 필요하면 방화벽/클라우드 보안 그룹에서 TCP `3690` 포트도 열어야 합니다.

서버 재부팅 후에도 자동 실행되게 하려면 `systemd` 서비스로 등록하는 방식이 좋습니다. 참고로 운영 환경에서는 `/root/SVN` 대신 `/srv/svn` 같은 별도 경로와 전용 계정을 사용하는 편이 안전합니다.

### Assistant

네. 해당 경로가 SVN **워킹 카피(checkout 폴더)**이고 `config.txt`가 SVN에 등록된 파일이라면, 수정 후 커밋하면 SVN 저장소의 내용도 변경됩니다.

```bash
cd /dotnet/Live_Astellia_Server_Svn/Config/Live/Server

svn status config.txt
```

수정한 파일이면 다음처럼 표시됩니다.

```text
M       config.txt
```

변경 내용을 확인한 뒤 해당 파일만 커밋하세요.

```bash
svn diff config.txt
svn commit config.txt -m "Update Live server configuration"
```

커밋하면 다른 서버가 같은 SVN 경로를 `svn update`할 때 변경된 `GLOBAL_DB_IP`, `SERVER_ID` 등도 내려받게 됩니다.

먼저 이 폴더가 실제 SVN 워킹 카피인지 확인하려면:

```bash
svn info
```

`URL`, `Repository Root` 등이 표시되면 맞습니다.

주의할 점은 이 파일이 서버별 환경 설정이라면 커밋하지 않는 편이 좋을 수 있다는 점입니다. 예를 들어 Gateway01 전용 값이라면 SVN 공통 설정을 바꾸게 되어 다른 서버에 영향을 줄 수 있습니다. 그런 경우에는 `config.txt`를 커밋하지 말고, 공통 템플릿 파일과 서버별 로컬 설정 파일을 분리하는 구성이 안전합니다.

### User

DecrementRef 이 함수의 역할은 무었인가요?

### Assistant

`DecrementRef()`의 역할은 **`ServerPacket`을 더 이상 사용하지 않는다는 표시를 하고, 마지막 사용자라면 풀에 반환하는 것**입니다.

즉 흐름은 원래 이렇게 설계된 것으로 보입니다.

```csharp
IncrementRef(); // 이 패킷을 사용할 주체가 하나 늘어남
DecrementRef(); // 이 패킷 사용이 끝남
```

`refCount`가 0이 되면 “이 패킷을 더 쓰는 곳이 없다”고 판단해서 `Dispose()`를 호출하고, `Dispose()` 안에서 `PoolManager`로 반환합니다.

문제는 현재 코드에서 [ServerPacket.cs](E:/ProjectA02/Trunk/Dev/Server/EgonServer/Packet/ServerPacket.cs:72)의 `Reset()`이 `refCount = 0`으로 만들고, [ServerController.cs](E:/ProjectA02/Trunk/Dev/Server/EgonServer/Controllers/ServerController.cs:2460)에서 `Build()` 후 `IncrementRef()` 없이 바로 [DecrementRef](E:/ProjectA02/Trunk/Dev/Server/EgonServer/Packet/ServerPacket.cs:82)를 호출한다는 점입니다.

Release 기준으로는:

```csharp
if (Interlocked.Decrement(ref refCount) == 0)
{
    this.Dispose();
}
```

이므로 `0 -> -1`이 되어 `Dispose()`가 호출되지 않습니다. 그래서 패킷이 풀로 돌아가지 않고 GC 부담이 늘어날 수 있습니다.

정리하면, `DecrementRef()` 자체는 “패킷 사용 완료 + 마지막이면 반환” 함수인데, 현재는 **초기 refCount 세팅과 호출 규칙이 맞지 않아 성능 문제가 생길 수 있는 상태**로 보입니다.

```csharp
완료 3번 => refCount -3
```

```csharp

```

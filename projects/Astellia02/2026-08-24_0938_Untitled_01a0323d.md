## 9. 개선 권고안

### 1순위: 대량 보상 집계 처리

1,000회의 보상 결과를 아이템별로 먼저 집계한 후 다음 작업을 한 번만 수행하도록 변경하는 것이 필요합니다.

- 기존 스택의 여유 수량 계산
- 필요한 신규 슬롯 수 계산
- 인벤토리 공간 확인
- 아이템 생성 및 예약
- 최종 보상 반영

목표 구조:

```text
현재:
1,000회 × 보상 계산
        × 슬롯 계산
        × 잔여 인벤토리 계산
        × 아이템 예약

개선:
1,000회 보상 결과 생성
→ 아이템별 수량 집계
→ 슬롯 및 잔여 인벤토리 한 번 계산
→ 아이템 종류별 예약 및 반영
```

확률 보상인 경우 단순히 기댓값에 1,000을 곱하면 기존 확률 동작이 변경될 수 있습니다. 보상 추첨 결과는 기존 규칙대로 생성하되, 인벤토리 검사와 지급 처리를 아이템별로 합산하는 방법이 안전합니다.

### 2순위: 잔여 인벤토리 계산 최적화

현재 슬롯 사용량을 인벤토리 타입별 카운터로 유지하면 다음과 같이 O(1)에 가까운 계산이 가능합니다.

```text
남은 슬롯
= 최대 슬롯
- 현재 사용 슬롯
- 예약으로 추가될 슬롯
```

아이템 추가, 삭제 및 이동 시 카운터의 정합성을 유지해야 합니다.

### 3순위: 메모리 할당 제거

잔여 인벤토리 계산 내부의 컬렉션 복사와 임시 객체 생성을 제거해야 합니다. 호출당 할당을 줄이지 않으면 다중 사용자 실행 시 GC에 의한 추가 지연이 발생할 수 있습니다.

### 보조 방안: 청크 처리

근본 개선을 즉시 적용하기 어려운 경우, 대량 보상을 여러 틱으로 분할하면 한 틱의 장시간 점유는 완화할 수 있습니다.

다만 이 방법은 총연산량과 메모리 할당을 줄이지 못하므로 임시 안전장치로 사용하는 것이 적절합니다. Actor 인벤토리 상태의 정합성 문제 때문에 전체 보상 처리를 단순히 다른 스레드로 이동하는 방식은 우선 해결책으로 권장하지 않습니다.

## 슬롯 계산 시 추가로 고려할 사항

단순히 “인벤토리에 해당 Item ID가 존재하는가”만 확인하면 부족합니다.

- 기존 스택이 최대 수량에 가까운 경우
- 보상 총수량이 최대 스택을 초과하는 경우
- 스택 불가능한 아이템
- 기간제 등 같은 Item ID여도 합칠 수 없는 아이템
- 재화처럼 인벤토리 슬롯을 사용하지 않는 아이템
- 상자를 전부 사용하면서 상자 슬롯 자체가 비워지는 경우

필요 슬롯은 다음 방식으로 계산해야 합니다.

```text
필요 슬롯
= ceil(
    (총 지급 수량 - 기존 호환 스택의 여유 수량)
    / 최대 스택 수량
  )
```

또한 상자를 모두 사용하여 원본 상자 슬롯이 사라진다면 그 슬롯도 가용 슬롯에 포함해야 합니다. 그렇지 않으면 실제로 지급 가능한데도 인벤토리 부족으로 처리할 수 있습니다.

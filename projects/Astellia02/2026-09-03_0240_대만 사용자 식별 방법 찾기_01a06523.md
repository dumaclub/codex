### 권장 구현

로그인 또는 게임 게이트웨이에서 사용자의 실제 공인 IP를 GeoIP 데이터베이스로 조회합니다.

```text
203.x.x.x → TW → 대만 접속
118.x.x.x → KR → 한국 접속
```

결과는 ISO 국가코드로 저장하는 것이 좋습니다.

```text
detected_country = "TW"
declared_region  = "TW"
billing_country  = "TW"
is_proxy         = false
checked_at       = 로그인 시간
```

선택지는 보통 다음과 같습니다.

- 직접 게임 서버에 TCP/UDP로 접속한다면 소켓의 `RemoteEndPoint` IP 조회
- 웹/API가 Cloudflare를 거친다면 `CF-IPCountry: TW` 사용
- 자체 서버에서 판별한다면 MaxMind GeoIP2 또는 GeoLite2 Country DB 사용

Cloudflare는 원본 방문자의 국가를 `CF-IPCountry` 헤더로 제공하며, 대만은 `TW`, 한국은 `KR`입니다. 단, 이 헤더는 외부에서 위조할 수 있으므로 **오리진 서버가 Cloudflare를 통해 들어온 요청만 신뢰하도록 제한**해야 합니다. [Cloudflare 공식 문서](https://developers.cloudflare.com/fundamentals/reference/http-headers/)

### 판별 로직 예시

```text
1. IP 국가가 TW이고 VPN/프록시가 아님
   → 대만 접속자로 판정

2. IP 국가가 JP지만 계정 지역·결제 국가가 TW
   → 대만 사용자일 가능성 높음, 현재 일본 체류 또는 VPN 가능

3. IP 국가가 TW지만 계정 지역·결제 국가가 KR
   → 여행·로밍·VPN 가능, 확정하지 않고 불일치 상태로 처리

4. 정보가 충돌
   → 사용자에게 서비스 지역을 직접 선택하도록 함
```

IP 국가 판별은 국가 수준에서는 비교적 정확하지만 VPN, 회사망, 모바일 로밍, 프록시 때문에 오판할 수 있습니다. MaxMind도 IP 위치가 특정 개인이나 국적을 식별하지는 못하며, 자사 국가 판별 정확도를 약 99.8%로 추정하면서도 VPN·모바일망 등에 따른 예외를 명시합니다. [MaxMind 정확도 안내](https://support.maxmind.com/knowledge-base/articles/maxmind-geolocation-accuracy)

따라서 추천 정책은 다음과 같습니다.

- `IP 국가`는 최초 기본값과 운영 통계에 사용
- `사용자가 선택한 서비스 지역`은 계정에 별도 저장
- 전화번호 `+886`, 중국어 번체, `Asia/Taipei` 시간대는 보조 신호로만 사용
- 결제나 법적 제한이라면 IP만으로 결정하지 않음
- 국적이 정말 필요하면 사용자 동의하에 별도 인증
- GeoIP DB는 계속 갱신
- IP와 판별 결과의 보관기간을 최소화하고 개인정보 처리방침에 반영

즉, 일반적인 게임 운영 목적이라면 **“로그인 IP가 `TW`인지 확인하고, 계정의 서비스 지역 선택값과 함께 사용”**하는 방식이 가장 안정적입니다.

- 이 컬럼은 로그인 시 덮어쓰므로 **최근 접속 IP**이며 접속 이력은 아닙니다.

- VPN·해외 체류·모바일 로밍 사용자는 실제 국적과 다를 수 있습니다.
- 따라서 판별 결과는 “대만 국적자”가 아니라 **“최근 대만 IP로 접속한 계정”**입니다.

### 이미 구매한 사용자 복구

상품 `401014`는 `SalesLimit=9999999`이므로 오류 당시에도 BM 엔티티는 생성됐을 가능성이 높습니다. 수정 코드 배포 후 재로그인하면 `AddBMEntity()`가 `SetPrivilegeBmItem()`을 다시 호출하여 다음처럼 복구될 수 있습니다.

```text
endDate = bmEntity.lastRefreshDate + 28일
```

다만 반드시 DB에서 다음을 확인해야 합니다.

- `bmStoreId = 401014`
- `buyCount >= 1`
- `lastRefreshDate`가 실제 구매 시각인지
- `endDate`가 기본값인지
- 동일 사용자가 오류 기간 중 여러 번 구매했는지

여러 번 구매한 사용자는 주의가 필요합니다. 로그인 복원 로직은 `buyCount × 28일`이 아니라 기본적으로 `lastRefreshDate + 28일`만 설정하므로, 중복 구매분은 별도 보정이 필요할 수 있습니다.

### 로그의 별도 문제

`resultCode=1000006`인데도 `GiveBillingItem()`이 실행된 것은 `#if DEBUG`와 `UseCheat` 설정으로 영수증 실패를 성공 처리했을 가능성이 높습니다. 이 경우:

### Assistant

다이아 획득은 사용자 로그 DB의 `gamelog_partition` 테이블에서 `logId = 5012(diaAdd)`로 확인할 수 있습니다.

```sql
SELECT
    idx,
    date,
    uId,
    charId,
    p1 AS itemId,
    p2 AS gainAmount,
    p3 AS gainType,
    parameterString
FROM gamelog_partition
WHERE logId = 5012
  AND uId = :userUid
  AND date BETWEEN '2026-08-21 10:45:00'
               AND '2026-08-21 11:00:00'
ORDER BY date, idx;
```

`parameterString`은 다음 형태입니다.

```json
{
  "type": "Dia",
  "pCnt": 1000,
  "amt": 400,
  "cnt": 1400
}
```

- `pCnt`: 지급 전 다이아
- `amt`: 획득한 다이아
- `cnt`: 지급 후 다이아
- `p2`: 획득 수량
- `p3`: 획득 경로 또는 획득 타입

이번 특권 상품 `401014`의 보관함 수령과 다이아 지급을 함께 확인하려면 다음처럼 조회하는 것이 좋습니다.

```sql
SELECT
    idx,
    date,
    logId,
    uId,
    charId,
    p1,
    p2,
    p3,
    parameterString
FROM gamelog_partition
WHERE uId = :userUid
  AND date BETWEEN '2026-08-21 10:45:00'
               AND '2026-08-21 11:00:00'
  AND (
        logId = 5012
        OR (logId = 14005 AND p2 = 401014)
      )
ORDER BY date, idx;
```

판단 기준은 다음과 같습니다.

- `logId = 14005`, `p2 = 401014`: 특권 상품을 보관함에서 수령한 기록
- `logId = 5012`, `p2 = 400`: 다이아 400개가 실제 지급된 기록
- `parameterString`의 `cnt - pCnt = amt`: 잔액 반영까지 정상

따라서 `14005`만 있고 `5012`가 없다면, 보관함 수령은 처리됐지만 다이아 지급 경로까지 실행되지 않았거나 지급 데이터가 다이아로 처리되지 않은 것입니다.

- `SC_DungeonTimeLimitList.guildChanelGroup` 누락과 브로드캐스트 미노출은 패킷 경로 자체는 다르지만, 로컬 서버의 논리적 Game/GlobalGame 타입이 물리 서버 ID `100`의 Gateway/Develop 타입으로 치환되는 공통 문제가 원인일 가능성이 높습니다.

수정 지점은 로컬 단일 서버의 ZMQ/Broadcast 발신 시 물리 서버 ID `100`이 아니라 논리적 발신 서버 ID·타입(Game `1001` 등)을 유지하도록 하는 부분입니다. 동시에 Gateway의 타입 불일치 분기에 `fromServerId/type`, `bindServerId/type`, 패킷 ID 로그를 추가하면 수정 후 결과를 명확하게 검증할 수 있습니다.

### User

길드 창고로 아이템이 갔다면 브로드캐스팅 메세지도 안나오는게 정상 아닌가요? 길드에서 획득해도 브로드캐스팅 메세지가 원래는 출력 되어야 하나요?

### Assistant

현재 서버 구현 기준으로 확인해 보겠습니다. 길드 창고 전환 뒤에도 알림 생성 함수를 호출하는지, 그리고 `ItemAdMessage` 조건이 개인 획득과 길드 획득에 동일하게 적용되는지를 코드에서 다시 따라가겠습니다.

### Assistant

아닙니다. 현재 서버 코드 기준으로는 길드 창고로 들어간 아이템도 조건을 만족하면 브로드캐스팅 메시지가 출력되어야 합니다.

처리 순서는 다음과 같습니다.

```text
보스 아이템 드롭
→ 길드 소유 보스이면 개인 인벤토리 대신 GuildItemAdd 요청
→ 길드 창고 추가 성공 응답(SC_ZMQ_GuildItemAdd)
→ NotifyItemGainMessage 호출
→ ItemAdMessage 조건 확인 후 브로드캐스팅
```

`RepHandler.cs`의 `SC_ZMQ_GuildItemAdd` 성공 처리에서 `NotifyItemGainMessage`를 별도로 호출하도록 구현되어 있습니다. 즉, 저장 위치가 길드 창고라는 이유로 획득 방송을 생략하지 않습니다.

야니토르 영웅 장비도 다음 조건을 만족합니다.

- `ItemRank = 4`: 영웅 등급
- `ItemAdMessage = 3 (AddAll)`: 획득 경로와 관계없이 알림 대상

또한 두 알림은 성격이 다릅니다.

- `CS_ZMQ_GuildNotify`: 길드 창고 변경을 길드 측에 알리는 처리
- `NotifyItemGainMessage`: 희귀 아이템을 획득했다는 전체 브로드캐스팅 메시지

따라서 QA 기대사항인 “길드 창고에 영웅 장비가 들어가더라도 획득 브로드캐스팅이 출력되어야 한다”가 현재 코드 동작과 일치합니다. 메시지가 나오지 않은 것은 정상 동작이 아닙니다.

다만 로그의 `Gateway task : cmdType(Broadcasting)`만으로는 그 작업이 길드 알림인지 전체 획득 방송인지 패킷 종류까지 구분되지는 않습니다. 코드상 `NotifyItemGainMessage` 호출 대상인 것은 확인되므로, 다음 확인 지점은 `NotifyItemGainMessage` 호출 직후부터 `SC_NotifyMessage` 클라이언트 송신 전까지입니다. 앞서 확인한 로컬 서버의 Game/Gateway/Develop 타입 불일치가 이 구간에서 메시지를 걸러냈을 가능성이 높습니다.

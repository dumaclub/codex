        case eSpawnUnitState.SpawnReserved:

2차 생성:

    → SpawnUnit 복사본 U2
    → 보르키 Actor B

### Assistant

네, 맞습니다. `FirstspawnTime=10` 때문에 첫 번째 보르키가 생성됐습니다. 다만 `12시`에 생성된 것이 아니라, 존 생성 10초 후인 `11:54:53`에 먼저 생성됐습니다.

두 생성은 서로 다른 타이머에서 발생했습니다.

| 생성 | 기준 | 시각 |
|---|---|---|
| 첫 번째 보르키 | 존 생성 + `FirstspawnTime=10초` | 11:54:53 |
| 두 번째 보르키 | 서버 스케줄 `4501` 시작 | 12:00:00 |

### 첫 번째 생성

```text
11:54:43.299 CreateZoneModel zoneId:859001
11:54:53.367 NormalBossSpawn bossId:2320002
```

`ConditionType=NormalSpawn`이므로 존 기본 스폰 대상이고, `FirstspawnTime=10`이므로 존 생성 10초 후 예약 스폰됩니다.

```text
11:54:43 + 10초 ≈ 11:54:53
```

따라서 첫 번째 보르키는 12시 이전부터 이미 존재했습니다.

### 두 번째가 정확히 12시에 생성된 이유

보르키의 동일한 `MonsterSpawnData 200001`이 서버 스케줄에도 연결되어 있습니다.

```text
ServerSchedule 4501
    → 시작 시각 12:00
    → ServerEventTask 340101
    → ServerEventData 200001
    → MonsterSpawnData 200001
    → CharacterBaseId 2320002
```

그래서 12시에 스케줄 `4501`이 시작되면 `OnBossAction()`이 다시 동일한 `MonsterSpawnData 200001`을 가져옵니다.

```csharp
var monsterSpawnData =
    LoaderMonsterSpawnData.GetMonsterSpawnData(
        eventTask.ServerEventData); // 200001
```

그리고 월드던전이므로 다음을 호출합니다.

```csharp
ZoneManager.Instance.SpawnBossMonster(
    monsterSpawnData.ZoneId,       // 859001
    spawnKey,                      // 23200021
    0,
    scheduleModel,
    monsterSpawnData);
```

실제 로그입니다.

```text
12:00:00.194 SpawnBossMonster [1] zoneId:859001
12:00:00.194 SpawnBossMonster [2]
               spawnKey:23200021
               channelKey:85900108
12:00:00.194 SpawnBossMonster [3]
               zoneModel:False
```

즉, 12시 생성은 `FirstspawnTime`에 의한 것이 아니라 별도의 서버 스케줄 `4501`에 의한 것입니다.

### 중요한 데이터 충돌

현재 하나의 `MonsterSpawnData 200001`이 두 가지 용도로 동시에 사용되고 있습니다.

```text
ConditionType=NormalSpawn
FirstspawnTime=10
```

이 설정 때문에 존 생성 시 자동 스폰됩니다.

동시에:

```text
ServerSchedule 4501
→ ServerEventTask 340101
→ MonsterSpawnData 200001
```

이 연결 때문에 12시에도 스폰 요청이 발생합니다.

구조적으로 다음과 같은 상태입니다.

```text
MonsterSpawnData 200001
    ├─ 일반 스폰 설정 → 존 생성 10초 후 생성
    └─ 스케줄 연결    → 12시에 다시 생성
```

### RespawnTime=28800은 12시 생성과 무관

`RespawnTime=28800`은 보스가 죽은 후 다시 생성되기까지의 시간입니다.

```text
28800초 = 8시간
```

따라서 다음 의미입니다.

```text
보르키 사망
→ 8시간 대기
→ 리스폰
```

12시 정시 생성에는 영향을 주지 않습니다.

### 기존 보스가 있는데 왜 12시 생성이 차단되지 않았는가?

원래라면 첫 번째 보르키가 살아 있으므로 12시 요청이 들어와도 상태 검사에서 차단되어야 합니다.

하지만 앞서 확인한 것처럼 `SpawnModel.GetSpawnUnit()`이 상태 객체를 그대로 반환하지 않고 복사본을 반환합니다.

```csharp
return _spawnUnitInfoList.Select(x => x.CopyTo());
```

첫 번째 보르키의 `Spawn` 상태는 첫 번째 복사본에만 저장됩니다. 12시에 다시 요청하면 원본 상태 `None`에서 새로운 복사본을 만들기 때문에 생성 가능 상태로 판단합니다.

따라서 전체 원인은 다음 세 조건이 결합된 것입니다.

```text
1. NormalSpawn + FirstspawnTime=10
   → 11:54:53 첫 번째 생성

2. scheduleId=4501
   → 12:00 두 번째 생성 요청

3. SpawnUnit을 복사해서 상태 관리
   → 기존 보스 감지 실패
   → 두 번째 액터 생성 허용
```

보르키가 스케줄에만 생성되어야 한다면 데이터는 다음처럼 구성하는 것이 적절합니다.

```text
ConditionType  = OnTimeSpawn
FirstspawnTime = -1
RespawnTime    = -1
```

`FirstspawnTime=-1`이면 존 생성 시 자동 스폰을 건너뛰고, 12시 스케줄에 의해서만 생성됩니다.
